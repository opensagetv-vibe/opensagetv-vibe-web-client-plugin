# SageTV Web Player 3.2.1 — GFX reset recovery

Date: 2026-09-24. Exact baseline: supplied
`SageTV-WebPlayer-Local-Plugin-v3.2.0.zip`.

## What was established

The supplied screenshot says `GFX connection ended: Connection reset`. In v3.2.0
this text is generated by the Java MiniClient GFX socket loop. It is not an
FFmpeg error. The screenshot does not identify why the native socket was reset,
whether it happened during startup or playback, or the server-side exception.
No new server log was supplied. Older Android logs are not treated as evidence
of the cause of this WebPlayer failure.

Inspection found that v3.2.0 rejected `RECONNECT_SUPPORTED=TRUE` with result 1 and
closed the complete session on a GFX exception. The browser nevertheless kept
opening its HTTP event stream against the already-closed native session. Its
render-only/fullscreen CSS also hid the toolbar needed to recover. These are
confirmed code-level gaps, not proof of the original reset's root cause.

The native MiniClientSession.java file was identical between the supplied
v3.1.1 and v3.2.0 packages. Therefore this update does not claim the new MPEG-TS
settings introduced the socket reset.

## Changes

- Accept native reconnect negotiation and use connection type 5 only after the
  server enabled reconnect and the first GFX STARTFRAME was received. A reset
  during initial negotiation is a terminal failure, not an unsafe resume.
- Try three recovery handshakes, with delays 0/150/350 ms and 5-second socket
  connect/read timeouts. A successful handshake keeps media and image handles.
  No browser playback restart is issued for a successful GFX-only reconnect.
- Drop a partially received frame on connection failure; restart parsing at a
  fresh header on the new socket. Do not replay a stale header or command body.
- Keep event/reply writes serialized on a stable lock across socket replacement.
  While recovering, user input is rejected rather than acknowledged without
  being sent. Event-channel write failure wakes the GFX reader that owns recovery.
- Add explicit media-worker readiness before starting the GFX worker. Close
  active and in-progress sockets before player cleanup; prevent a late handshake
  from reviving a closed session. Respect server GFX DEINIT as a normal close.
- Retire an existing in-plugin session with the same normalized server/client ID
  before opening a replacement. Report that replacement to the old tab. Stopping
  an old session ID does not affect a newer one. This is not a global identity
  lock against external clients, hostname aliases, or another plugin instance.
- Stop HTTP stream/long-poll retries once native closure is known. Check native
  status after HTTP EOF so a missed terminal event does not cause an empty loop.
  A transient HTTP-only disconnect can still reopen its HTTP stream.
- Reveal Reconnect and Download diagnostics after terminal failure, even in
  render-only/fullscreen view. Keep the session ID available for diagnostics and
  preserve a browser playback snapshot captured at failure.
- Add a bounded native trace (64 entries), last command names and sizes, phase,
  first-frame/negotiation state, recovery counts, and the original transport error.
  New property tracing records names, not values. The full existing browser
  diagnostic export may contain addresses/session IDs/media metadata; review
  before public sharing.

## Installation

Close other browser MiniClient tabs for the first test. Stop SageTV/Jetty, retain
the previous WAR, then replace `jetty/webapps/SageTVWebPlayer.war` with the ZIP's
`dist/SageTVWebPlayer.war`. Restart SageTV/Jetty and hard-refresh with Ctrl+F5.
Confirm **3.2.1** in the toolbar.

The separately supplied `SageTVWebPlayer-v3.2.1.war` must be renamed to
`SageTVWebPlayer.war` when installed. Do not deploy both versioned and unversioned
WAR files: that would create separate web applications with independent sessions.

If an old exploded app is retained, stop Jetty and remove only its generated
`jetty/webapps/SageTVWebPlayer/` directory. Do not delete Sage.properties, saved
client profiles, recordings, or the vendor cache. The local-plugin installer is
also included under `dist/local-install/SageTVPluginsDev.d`.

No Sage.jar, Jetty port, FFmpeg/MIM, or streaming-settings change is required.
Existing pinned player assets/cache remain in use. Python is needed only for
some development tests and packaging, not by the installed plugin.

## Validation and limits

See `VALIDATION-v3.2.1.txt` for actual results. The new native suite uses real
loopback sockets and TCP resets with a synthetic SageTV peer. It checks recovery,
rejections, partial packets, cancellation, terminal startup failure, shutdown,
trace bounds and duplicate-ID replacement. The new Chromium suite runs the
production DOM/JavaScript with mocked HTTP. It checks terminal-state handling,
HTTP/native distinction, controls, diagnostics, reconnect and mobile layout.

The existing FFmpeg, streaming servlet, caption, browser settings/rendering,
playback lifecycle and Java 8 target checks are also run. Physical GPU, actual
vendor/MSE playback and live SageTV/SageMC are not validated here. Successful
mock/loopback recovery is not a physical-server pass. The screenshot's original
reset cause remains undiagnosed.

If another reset occurs, download diagnostics **before clicking Reconnect** and
capture `sagetv_0.txt` covering the same timestamp. The command/phase and first-
frame fields distinguish a handshake failure from a recoverable established UI.
