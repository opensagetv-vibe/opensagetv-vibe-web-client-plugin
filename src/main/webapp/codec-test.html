SageTV Native HLS Codec Test

This page tests the browser's native HLS decoder with synthetic media created by the same server-side FFmpeg configured for SageTV. It deliberately does not use hls.js. Tests A-C are the original small controls; tests D-E reproduce the known codec/resolution/frame-rate/audio parameters of the real 1280×720p59.94 MPEG-2/AC-3 recording while keeping the media content synthetic.

Checking test streams…

A — MPEG-2 360p30, Copy

Original control: MPEG-2 Part 2 video + AAC stereo in HLS MPEG-TS. Video uses -c:v copy.

Not tested

B — MPEG-2 360p30 → H.264

The exact A source is converted to H.264 while AAC is copied. This is the baseline compatibility transcode.

Not tested

C — H.264 360p30, Copy

H.264 + AAC in MPEG-TS is repackaged as HLS with no video encode. This controls for HLS/remux behavior.

Not tested

D — Real-file profile MPEG-2, Copy

Synthetic MPEG-2 Main 1280×720 progressive 59.94 fps, ~6.3 Mb/s, English AC-3 5.1 384 kb/s + Spanish AC-3 stereo. Video is copied; English audio is converted to AAC stereo just like the WebPlayer compatibility path.

Not tested

E — Same real-file profile → H.264

The exact D synthetic source is transcoded to H.264 at 1280×720p59.94 with source cadence preserved; English AC-3 is converted to AAC stereo. This is the direct D/E A/B comparison.

Not tested
How to interpret D/E: D and E start from the exact same synthetic 720p59.94 MPEG-2/AC-3 source. If D gives audio/timeline but videoWidth=0 while E reaches 1280×720, the difference is native MPEG-2 video decoding rather than resolution, frame rate, progressive scan, HLS segmentation, or the selected source audio. The fixture does not reproduce the programme's actual picture content or closed-caption payload.

Tip: run this page directly on the iPhone/iPad or Safari device being evaluated. All players are muted so the Run button can start them without audio autoplay restrictions.
